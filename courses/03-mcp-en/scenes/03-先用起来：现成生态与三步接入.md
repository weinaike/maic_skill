## 讲稿

Before we write any code, remember one principle that will save you a lot of time. The capability you need has probably been wrapped by someone already. For the everyday needs of research, official and community Servers already exist. @[text_card_fs]

Take these three types, shown in the three cards left to right. filesystem lets the Agent read and write files in the folders you designate. fetch lets it grab webpages and read online docs. And there are database Servers of all kinds, letting the Agent query SQLite or Postgres directly. @[text_card_fs]

Literature search, web material, database queries. None of these are yours to write. When you pick an off-the-shelf Server, check three things. Does the feature match your need? Is it still maintained? Are the permissions it asks for reasonable?

So when do you build it yourself? Here's a rule of thumb in one line: combine what's common, build what's unique. General capabilities, you compose from off-the-shelf Servers. Only the logic unique to your lab is worth wrapping as your own MCP. Say, that special sample-processing pipeline of yours. @[text_motto]

Plugging in a ready-made Server is easy. Three steps. Step one, configure. In Claude Code, it's one command, claude mcp add, or an entry in the project's MCP config file. WorkBuddy has its own plug-in entry too. We demoed it in the intro course. Forgot it? Go back and replay that part. @[text_step1]

Step two, confirm. If the Server's tool list shows up in your client, you're connected. Step three, try it out. Pick one tool and actually call it once. Check whether the result is right.

Once these three steps are done, you'll have a real feel for what an MCP looks like inside a client. Next, we'll take the one you write yourself and make it look just like this.
