## 讲稿

在动手写代码之前，先记住一个能帮你省下大量时间的原则：你要的功能，大概率已经有人封装好了。科研里的高频需求，官方和社区几乎都有现成的 Server。 @[text_card_fs]

比如这三类：filesystem，让 Agent 直接读写你指定的目录里的文件；fetch，让 Agent 去抓网页、读在线文档；还有各种数据库 Server，让 Agent 直接查 SQLite、Postgres 里的数据。文献检索、网页资料、数据库查询，这些都不用你自己写。 @[text_card_fetch]

那什么时候才需要自己动手？给大家一个判断口诀，就八个字：现成的组合，独有的自研。通用能力用现成的组合起来；只有你实验室独有的业务逻辑——比如你那套特殊的样品处理流程——才值得自己封装成 MCP。 @[text_motto]

要用现成的也简单，三步。第一步，配置：Claude Code 里一条命令 claude mcp add，或者写进项目的 .mcp.json；WorkBuddy 里也有对应的接入入口——入门课的第 7、8 页演示过，忘了可以回去翻。 @[text_step1]

第二步，确认：客户端里能看见这个 Server 的工具列表，说明连上了。第三步，试用：挑一个工具实际调用一次，看结果对不对。

这三步走完，你对"一个 MCP 在客户端里长什么样"就有直觉了。接下来，我们就把自己写的那个，也变成这个样子。
