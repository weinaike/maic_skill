# 讲稿写作规范（speech-style）——写给耳朵，不是眼睛

讲稿是 TTS 朗读的剧本 + 听觉学习者的全部信息源。本规范由 03-mcp 课 46 句讲稿的
逐句审查蒸馏而来，每条附真实反例→正例。生成讲稿（workflow-generate）与审查
（review-checklists C4/C5）都以本规范为准。

## 十条规范

### 1. 一段一要点，≤120 字；单句 ≤60 字
一段超过 120 字，听众跟丢；单句超过 60 字，TTS 一口气念不完。
> 反例（§8 原稿，180 字三工具一段）：先说调试工具。第一个，MCP Inspector……第二个，客户端日志……第三个……
> 正例：拆两段——"先说调试工具。MCP Inspector 是官方调试器……"＋"再给大家一个科研同学最该养成的习惯……"

### 2. 画布是提词器，不是剧本
画布上写的要点文字**不照念**。讲稿讲的是：为什么、怎么理解、正反例、口诀——
画布负责"看到"，讲稿负责"听懂"。

### 3. 承接链完整：首段承上页，末段引下页
- 首段承接上页（指代或递进）："上一讲我们搭起了框架——但它会干活吗？"
- 末段收口或引出下页；quiz 前给预告，pbl 页给行动指引
- 课程首尾呼应：第一页立目标，最后一页回扣目标 + 下一课预告

### 4. 金句必须口头化
画布副标题/口诀若承载核心信息，讲稿里必须说出原话——**听觉学习者看不到画布**。
> 反例：§7 画布写"工具好不好用，一半取决于描述写得好不好"，讲稿只讲描述要点，金句没出口
> 正例：讲稿补一句"记住一句话：工具好不好用，一半取决于描述写得好不好"

### 5. 指代与版式一致
"看左边/右下角/这张卡"必须与实际布局一致（生成后对照 preview 校验）。
方位指代优先于"如图所示"（音频里没有"如"什么图）。

### 6. TTS 朗读安全：符号写读法
| 讲稿里不要出现 | 写成 |
|---|---|
| `N×M` | N 乘 M |
| `A→B`、`A|B` | 从 A 到 B、A 或者 B |
| `data://`、`.mcp.json` 式符号串 | 自然语言描述（"模板地址能带路径参数"） |
| `YYYY-MM-DD` | 年月日格式 |
| `80%` | 百分之八十 |

命令与代码名（`claude mcp add`、`fastmcp`、`Literal`）**可以保留**——听众要照着打，
逐词朗读正好；但只保留名称本身，不把整行代码念进讲稿。
括号内容会被 TTS 读出来——括号里只放该读的话。

### 7. 术语三段式：首现"英文+中文解释"，之后统一叫法
> 正例："MCP 就是来解决这件事的开放标准——Model Context Protocol，模型上下文协议。"
之后全课只用一个叫法（说 MCP 就一直 MCP，不中途换成"模型上下文协议"）。

### 8. 句式多样性：同一引入句式全课 ≤2 次
> 反例："给大家一个速记"（§2）＋"给大家一个判断口诀"（§3）＋"选型口诀一句话"（§6）
> 正例：三处保留最有力的一处，其余改为"记住一条""一句话总结"等自然变化。

### 9. 时长纪律：字数 = 分钟 × 350（豆包实测语速）±15%
- 讲稿里**不写死具体时长数字**（"先花两分半钟"）——时长对账会改大纲，讲稿跟着失真
- 列举超过三项必须分段；每页至少留一个停顿点（问句或短句收尾）
- **口径分相位**（防误判）：字数口径只适用于**配音前**（生成期估算）；音频合成后，
  时长真相 = 实测音频秒数 + 活动缓冲（quiz 答题/pbl/翻页），审查应按 voice.lock 的
  duration 对账 outline 分钟数，而不是回头用字数反推（03-mcp content r3 C-01 实例）

### 10. 听觉友好：短句、问句、画面感
- 多用问句推进（"但它会干活吗？还不会。"）
- 多用具象比喻（"会聊天的脑子""插座与插头"）——听觉没有图像，比喻就是图像
- 结论句放在段尾，慢而清晰；口诀给"八个字"这类结构预告，帮听众记住
